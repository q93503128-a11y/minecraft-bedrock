# GT RPG — 던전 입구 및 재사용 공간 설계

2026-11-24. 사용자가 제시한 핵심 변경: **입장 전 난이도 선택, 여러 던전, 클리어한 입구는 일회용, 패배하면 입구 유지**. 월드에 입구만 자연 생성하고 별도 공간 재사용은 권장 설계안. 구체 생성 빈도/구조물/파티/보상 정산은 추가 검토 대상. 구현 미착수.

## 1. 구조
- 생존 월드에는 실제로 탐험할 수 있는 작은 입구 구조물(폐묘, 신전 입구, 얼음 동굴 입구, 네더 성채 입구)을 지역에 맞게 자연 생성. 기존 바닐라 구조물/월드 생존/채굴/건축 유지. 입구와 내부가 모두 실제 월드에 매번 생성되는 방식 대신 입장 시 전용 던전 공간으로 이동하는 방식 권장.
- 같은 종류의 입구 여러 개는 동일한 던전 템플릿을 재사용. 각 입구는 차원+좌표+영구 고유 ID로 식별. 입구의 사용 여부는 세계 공용으로 저장(플레이어마다 다시 사용할 수 없는 방향). 성공 시 **입구 활성화 기능만 비활성화**, 구조물 자체는 폐허로 남기는 가안. 새 입구는 새로운 탐험/파밍 기회. 입구 파괴/재설치/복제/청크 재로딩으로 사용 횟수 초기화 불가.
- 이전에 제안한 최초 클리어 후 모험가의 서에서 무한 무료 보스 소환은 일회용 입구 규칙과 충돌하므로 현 설계에서는 채택하지 않는다. 강화 난도도 새로운 미사용 입구에서 바로 선택(이전 기본 난도 클리어 강제 없음). 별도 승급 도전은 기존 반복 가능 규칙 유지.

## 2. 던전 후보
기존 보스와 적을 재사용하여 아래 네 종류의 주요 던전을 우선 검토. 크기/방 수는 가안이며 추가 소형 던전은 이후 논의.
| 던전 | 입구 | 기본 미니보스 → 보스 | 방 구성 후보 |
| --- | --- | --- | --- |
| 지하 묘지 | 평원/숲의 묘지·석조 입구 | 데스 나이트 Lv.8 → 리치 Lv.10 | 복도, 묘실, 숨겨진 상자, 보스방 |
| 사막 신전 | 사막의 사암 입구 | 미노타우로스 Lv.17 → 거신 Lv.20 | 함정 통로, 전투실, 보물방, 보스방 |
| 얼음 동굴 | 설원/빙원 동굴 입구 | 아이스 골렘 Lv.32 → 얼음 마녀 Lv.35 | 빙굴, 갈림길, 상자방, 보스방 |
| 악마의 성채 | 네더의 현무암 입구 | 오우거 Lv.43 → 마왕 Lv.50 | 성채 통로, 전투실, 보물방, 보스방 |
- 주요 던전은 약 4~6개 의미 있는 방(입구/복도 제외 여부는 맵 설계 시 확정)으로 시작. 고정된 레이아웃을 우선 쓰고 적/상자 배치를 소수 후보 위치에서 변경해 반복감 완화. 매번 전혀 새로운 구조물 생성이나 지나치게 긴 미로는 필수 아님.
- 일반/정예 몬스터 기본 행동 유지, 미믹은 별도 위장 개체로 진짜 개인 보상 상자를 대체/삭제하지 않음. 보스방 진입/제단 상호작용으로 보스 전투 시작 후보. 던전 내부 블록 파괴/설치, 포탈, 외부 순간이동 등 악용 차단 및 정상 탈출 방법은 테스트 필요.

## 3. 입장 전 난이도
- 입구 상호작용 시 던전명, 기본/강화 난이도, 추천 레벨, 몬스터/보스 레벨, 보상 차이를 표시. 기본은 각 던전 고정 레벨, 강화는 각 몬스터/보스 기본 Lv+3W(기존 사용자 승인 방향, 계수 가안). W는 세션 시작 시 확정. W=0이면 강화 중복 표시 불필요.
- 난이도는 해당 세션에만 적용. 다른 자연 몬스터/다른 파티/세계 위협도에 영향을 주지 않는다. 강화 성공 자체는 W 상승 아님. 강화 시 보상 레벨/XP 및 높은 희귀도·고유 장비 확률 상향, 확률 상한 유지.
- 별도 입장권/재료 소모 없음. 일반/강화 선택 모두 성공 시 해당 입구 소모. 실패 후 난이도 변경하여 재시도 가능.
- 친구와 함께 입장할 때는 가까운 플레이어의 명시적 참가 동의(초대/수락 후보). 월드 전체 동의는 승급 도전에만 필요. 한 명이 임의로 다른 플레이어를 끌고 가지 않음. 실제 참가 정책은 확정 전 가안.

## 4. 공간 재사용과 동시 입장
- 권장: 한 개의 던전 전용 커스텀 차원에 던전 종류별로 분리된 고정 전투 구역. 한 구역은 한 파티만 사용. 같은 종류의 여러 입구가 동일한 템플릿/구역을 참조할 수 있음. 다른 종류의 던전은 구역이 분리되어 있으면 동시에 이용 가능.
- 같은 종류 던전이 이미 진행 중이면 **입장 전 사용 중 안내**, 입구는 소모하지 않는다. 동시 이용이 필요해지면 기존 템플릿을 다른 빈 좌표에 복제하여 구역 풀을 확장. 처음부터 무한 인스턴스 생성하지 않음.
- 목표 Bedrock 버전에서 커스텀 차원 문제가 있으면 별도의 안전한 월드 내 공간 후보를 검토하되, 기존 유저 지형/건축/월드 데이터 덮어쓰지 않는다. 사용 중 아닌 구역은 엔티티를 유지할 필요 없음.
- 전용 구역 준비 완료 전 텔레포트하지 않는다. 구역 상태/입구 상태/플레이어 세션/원래 차원과 좌표를 저장하고, 리셋은 해당 구역에만 적용. 해당 세션 ID로 스폰된 몹·상자·잔류 투사체만 정리(다른 플레이어 소환수/월드 엔티티를 무조건 제거하지 않음). 세션 전환 시 소환 직업의 소유권/재소환/쿨타임 보존.

## 5. 입구 상태 및 승패
- 입구 미사용 → 사용 중(잠금) → 성공하면 클리어 완료(영구 소모), 실패/취소하면 미사용으로 복구. 사용 중에는 중복 입장 금지. 구역 준비 실패/빈 구역 없음/접속 종료만으로 소모 금지.
- 성공 조건 후보: 최종 보스 정상 처치. 참가자 개인별 기여 보상을 확정한 후 입구 소모를 같은 멱등 정산으로 기록. 숨겨진 방 전체 탐색 강제하지 않음. 보스 전투 전에 탐험/상자 수집 가능.
- 전멸/포기 시 입구 남고 초기화 후 재도전. 일부 사망 시 승급과 같이 관전(후보)하고 살아 있는 동료가 클리어하면 세션은 성공, 입구 소모. 정확한 사망/인벤 드롭/보상 자격은 추가 결정. 승급 관전 규칙은 변경 없음.
- 서버 종료/이탈: 세션 중단 또는 복구 시 성공이 기록되지 않았다면 입구 재사용 가능. 이미 성공/보상이 기록된 입구가 서버 재시작으로 재활성화되면 안 됨. 플레이어 복귀 실패 시 안전한 복귀 위치 저장/복구. 입구 사용 중 상태가 영원히 남지 않게 회수.
- 성공한 입구는 플레이어/파티가 달라도 재사용 불가. 같은 종류의 미사용 입구를 새로 찾아 반복 파밍할 수 있음. 입구별 영구 ID와 세션별 ID 구분.

## 6. 보상 악용 방지 — 제안
- 실패 후 입구가 유지되므로 매번 초반 상자만 열고 포기하면 무한 파밍이 될 수 있다. RPG 던전 전리품(상자/몬스터/보스)의 세션 보상 후보는 클리어 확정 시 지급; 실패하면 미확정 전리품 초기화. RPG XP도 실패 반복 악용 방지(예: 입구별 몹 슬롯/기여자 1회 인정 또는 클리어 시 정산)를 별도 결정. 사용자가 보상 유지 여부를 아직 결정하지 않았으므로 확정하지 않음. 바닐라 월드 정상 XP/드롭은 그대로.
- 개인 전리품 및 실질 기여 XP 원칙 유지. 가방 가득 참/접속 끊김 상태에서도 보상 영구 분실 및 두 번 지급 금지. 보스 소환 몹의 반복 보상 차단. 입구 생성 빈도와 이동 거리, 던전 보상 효율은 실제 탐험 시간 기준 조정해 탐험이 지나친 노가다가 되지 않도록 함.

## 7. 공식 근거 및 검증
- [Bedrock 1.26.50 업데이트](https://learn.microsoft.com/en-us/minecraft/creator/documents/update1.26.50): 커스텀 차원 JSON이 실험 기능에서 정식 지원으로 변경. [Dimension components](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/dimensionreference/examples/dimensioncomponents/components?view=minecraft-bedrock-stable): void generator 지원. [StructureManager](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/structuremanager?view=minecraft-bedrock-stable): 구조물 배치 지원. [TeleportOptions](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/teleportoptions?view=minecraft-bedrock-stable) 및 [TickingAreaManager](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/tickingareamanager?view=minecraft-bedrock-stable): 전용 공간 이동/청크 준비 후보.
- 커스텀 차원은 자동으로 파티별 인스턴스를 만들어 주는 기능이 아니다. 구역 예약/생성/정리/저장을 직접 설계. Script API 기반 차원 등록 튜토리얼의 Beta APIs 요건과 정식 JSON 차원 정의를 혼동하지 않는다. 대상 버전/Android/BDS 실기 확인 필요.
- 필수 테스트: 자연 입구 중복/기존 청크, 서로 다른 입구의 동시 사용, 같은 입구 연타/다른 파티, 난도 선택 및 W 스냅샷, 성공/실패/재입장/리셋, 성공 직후 재시작, 복귀 위치 파괴, 가방 만석, 죽음/이탈/관전, 소환수, 블록 편집 악용, 보상 중복. 모든 항목 NOT_RUN. 사용자 승인 전 코드/에셋 생성 없음.
