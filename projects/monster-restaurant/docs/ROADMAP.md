# Development Roadmap (quality gates, not time estimates)

## M0 — Project/bootstrap
- Confirm target Bedrock and stable APIs, namespace, UUID policy, license provenance, source layout.
- Inspect actual game references: hunting, food preparation, in-world restaurants, codex UI and Minecraft build style.
- Draft minimalist design system and test plan before heavy production.

## M1 — Vertical slice
- Normal hunting for two monsters → ingredients → readable food preparation → both eating and selling.
- At least one staff helper, a simple restaurant counter and useful income spend.
- Actual Bedrock import/play, in-game screenshots, small-window UI, restart persistence.

## M2 — Cooking and guide polish
- Expand dishes/stations only if each has distinct use.
- Unified cookbook/bestiary, short source-to-use explanations and natural discovery.
- Model, animation, cooking FX, kitchen SFX integrated; actual player feedback.

## M3 — Village / staff / economy
- Restaurant ownership, villagers/visitors, few clear job roles, wage rules, meaningful income sinks.
- Test rejoin, chunk unload, multiplayer order duplication, pathfinding and performance.

## M4 — Combat and world
- Wider natural monster ecology, selective bonus hunting tactics, appropriate food buffs, mining/farming tie-ins.
- Boss or rare hunt content only if the basic loop is complete and fun.

## M5 — Production validation
- Balance, Bedrock compatibility, 1P/MP, mobile/controller/GUI scales, packaging and source reproduction.
- Close out actual failures; include no claim of full readiness without runtime verification.

Do not fill content quotas mechanically or claim a milestone complete from file existence alone.
