- Java canon definitions, tier, maximum levels, canonical effect text, source-file hits and interaction-contract references are present in the generated roster and CSV matrix. Detailed Bedrock mapping and API evidence is recorded for `강건함`, `날 선 감각`, `정확한 조준`, `질긴 피부`, `가벼운 착지`, `튼튼한 폐`, `풍작`, `씨앗 챙기기`, `적게 먹기`, `든든한 한 끼`, `물갈퀴`, `낚시 감각`, `숨 오래 참기`, `추위 적응`, `광부의 손`, `벌목 요령`, and `빠른 발`; the other 132 entries remain unassessed or unported. Do not interpret roster registration as implementation.
- The three catalog discrepancies are kept explicit. Names, levels and effect descriptions follow `AUGMENTS.md`; stable catalog IDs follow the Java catalog.
- No Java-mod assets, external mobs or structures were copied. Vanilla resources are used.
- BDS exposed invalid assumptions in the first runtime attempt: flattened custom item components are experimental on this target and recipes need unlock data. Production input now uses stable `world.afterEvents.itemUse`; recipes explicitly use `AlwaysUnlocked`. The corrected build and core transaction/effect tests pass.
- Delayed UI responses are token-checked and player-leave cleanup releases the form lock. Static coverage verifies stale responses cannot clear a later lock; BDS pack load and GameTests pass with this code.
- `빠른 발` remains `NOT_PORTED`: BDS resets the general movement component, and a faithful persistent stable route is not established. `물갈퀴` now uses the stable underwater-movement component, which is reconciled from saved level and current water state each tick. The production handler passed all three velocity ratios and out-of-water restoration on BDS 1.26.62.1; Java's shared additive movement synergy with other augments is pending until those effects are ported, and real-client, multiplayer, and modifier coexistence checks remain open. See `docs/API_COMPATIBILITY_2026-11-06.md`.
- `광부의 손` and `벌목 요령` are class C pending future stable API changes: stable break events expose no vanilla mining-progress or speed mutation, the stable `InputButton` values are only Jump and Sneak, and custom hold-to-break reconstruction cannot reliably preserve touch/controller semantics. `풍작` and `씨앗 챙기기` are partial vanilla mappings: their synthetic BDS test verifies both independent rolls and the four common crop products/planting items, but live player harvesting and Java's tool-sensitive/modded crop drops remain untested.
- Core synthesis now uses a shared server-authoritative slot transaction. A BDS test confirms 3:1 conversion, duplicate and insufficient-input rejection, and exact inventory preservation when a full inventory cannot accept the result. Java's bulk synthesis control is not implemented yet.
- The isolated BDS runner now executes test hooks inside a copied production BP because entity dynamic properties are pack-scoped. It verifies the production selection transaction and production damage handlers without adding test hooks to the shipped add-on. The three defense tests use synthetic damage on unarmored simulated players; augment multipliers stack correctly in tested combinations, while natural landing/drowning and ordering against vanilla mitigation remain untested.
- `적게 먹기` remains `UNASSESSED`/`NOT_PORTED`. BDS confirms the stable exhaustion attribute setter accepts 1.25 and retains it after two ticks, with hunger/saturation unchanged by the write. This does not show that per-action exhaustion deltas can be intercepted before hunger processing; no effect is shipped and the candidate remains disabled. See the food-exhaustion investigation in `docs/API_COMPATIBILITY_2026-11-05.md`.
- `든든한 한 끼` is a partial port. BDS 1.26.62.1 emits `itemCompleteUse` for cooked beef after vanilla hunger/saturation update, although the stable reference describes chargeable-item completion. The handler uses the exposed food component when available and otherwise derives the vanilla saturation delta from adjacent ticks. The cooked-beef 8/16/24% curve and cap passed, but other food types/engine builds and unrelated same-tick saturation changes remain unverified.
- `낚시 감각` remains D/NOT_PORTED after stable API review and a BDS cast probe: the vanilla hook exposes no script timer component, and stable event types reveal rod use/spawn but no bite event or timer setter.
