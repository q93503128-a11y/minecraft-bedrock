# Headless Bedrock engine tests

These tests run in a separate GameTest behavior pack and are excluded from the player `.mcaddon`. `@minecraft/server-gametest` is beta and the runner enables the required GameTest experiment only in its disposable test world. No Windows client worlds are read or changed.

## Run

```powershell
npm ci
npm run verify
npm run build:engine-tests
npm run test:engine
```

The first engine run downloads the official BDS selected in `bds-runner.json`. Results and server files live under `.bds/`; the checked-in standard command expects exactly 55 registered tests and writes its JSON summary there. `test:engine` covers core candidate gating and transactions, selected combat damage sources, Urgent Steps at all three levels plus its refresh/expiry, Quick Feet stacking, and cancelled-hit exclusion, `마지막 힘` damage at exact 30%, above and below the threshold, all three levels on synthetic root melee and owned-projectile hits, and additive stacking with `날 선 감각` / `정확한 조준`; the shared Bumper Crop/Seed Saver handler using deterministic crop permutations and rolls; `든든한 한 끼` by consuming cooked beef through the production BP handler at levels 1–3 plus a saturation-cap case; `물갈퀴` by exercising production swim-speed scaling at levels 1–3 plus out-of-water reset; `숨 고르기` by checking its 60-tick idle gate and exact 10/20/30% movement component scaling; additive Catch Breath/Webbed Feet swimming; `빠른 발` at exact 3/6/9/12/15% movement component multipliers and its delayed additive Catch Breath acquisition; mutually exclusive `야행성` nighttime and `햇빛 체질` daytime movement at all three levels plus their shared Quick Feet interaction; diagnostic vanilla fishing-rod, breathable-air, freeze-buildup, attack-speed, furnace-fuel, Long Reach, Underwater Work and Brace knockback/component and Shield Grip shield-disable probes; production Pickup Hand item/XP collection at all three radii plus an outside-radius control and one shared diamond / 4 XP award between two simulated players; an entity death/loot API surface probe that checks cow loot from a dead entity; Loot Scoop exact 5/10/15% boundaries plus deterministic eligible-stack duplication and augment-core exclusion through a real player-attributed death event; Extra Piece ore-drop tests covering deterministic chance boundaries and block/tool loot under Silk Touch and Fortune; and an Ore Sense rare-core selection plus production refresh that verifies core consumption/level storage, saved-level 6/8/10-block radii, water exposure, buried-ore rejection, and owner-targeted particles. Four Rider production tests verify exact +10% / +20% / +30% horse movement values, baseline restoration after dismount, and an unowned-mount control; targeted `rider_probe` tests inspect riding seats, the movement writer, vanilla mount IDs, and missing jump-strength/input APIs. The Underwater Work probe measures underwater stone-breaking tick counts without Haste and at Haste amplifiers 0–4; it is diagnostic only and does not test or implement an augment effect. The Brace probe records stable melee hurt-event timing and player velocity, checks for a runtime knockback-resistance component, and does not implement the augment. The Shield Grip probe exercises an axe-blocked vanilla shield, its native cooldown category, the stable cooldown writer, offhand shield replacement, and the first successful post-disable block; it found that changing the category timer does not shorten the native disable state. This is diagnostic only; no Shield Grip effect is implemented. A separate SimulatedPlayer break confirms live `playerBreakBlock` event delivery. The loot surface probe records stable `entityDie` and `entityItemDrop` timing, killer attribution, and confirms `LootTableManager.generateLootFromEntity` can return cow beef for a dead entity. Production Loot Scoop still re-generates the table and may return an empty or different bundle; its duplication path uses a test-injected deterministic bundle and is not asserted to match the original drops. The ground `moveRelative` velocity probe did not produce valid control/level-1 measurements, so it is excluded; client walking and an actual sprint-reset transition remain unverified. The movement tests verify server component values, not visible client motion. The water test measures the production handler's swim-speed ratios. The crop test uses the same handler source copied from BP but supplies a synthetic block-break event payload instead of triggering a real player break. Precise Aim and Last Strength use synthetic projectile-attributed `applyDamage` events with a spawned arrow entity; they do not test actual arrow flight or collision. A physical-arrow experiment failed to hit and is recorded as such in the API compatibility report. The live Extra Piece event test does not assert its random proc during ordinary survival mining. Live crop harvesting, the client-visible drop, mobile/controller navigation and real online multiplayer still need review.

Rider jump strength remains unimplemented and Rider is disabled as a core candidate; the full suite checks only the speed half. `rider_probe` is run separately from `test:engine`.

`npm run test:brewing-probe` separately runs the `fast_brewing_api_surface_probe` on BDS; it only enumerates vanilla brewing-stand components and block states and is not a brew-timing or gameplay test.

The simulated-player test cannot provide trustworthy visual UI or a real form selection. Reconnect persistence, client import, mobile/controller navigation, multiplayer, and world restart are not verified by this suite. The runner resets only its own generated world on each run.
