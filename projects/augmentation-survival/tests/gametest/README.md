# Headless Bedrock engine tests

These tests run in a separate GameTest behavior pack and are excluded from the player `.mcaddon`. `@minecraft/server-gametest` is beta and the runner enables the required GameTest experiment only in its disposable test world. No Windows client worlds are read or changed.

## Run

```powershell
npm ci
npm run verify
npm run build:engine-tests
npm run test:engine
```

The first engine run downloads the official BDS selected in `bds-runner.json`. Results and server files live under `.bds/`; the checked-in command expects exactly thirty-six registered tests and writes its JSON summary there. `test:engine` covers core candidate gating and transactions, selected combat damage sources, `마지막 힘` damage at exact 30%, above and below the threshold, all three levels on synthetic root melee and owned-projectile hits, and additive stacking with `날 선 감각` / `정확한 조준`; the shared Bumper Crop/Seed Saver handler using deterministic crop permutations and rolls; `든든한 한 끼` by consuming cooked beef through the production BP handler at levels 1–3 plus a saturation-cap case; `물갈퀴` by exercising production swim-speed scaling at levels 1–3 plus out-of-water reset; `숨 고르기` by checking its 60-tick idle gate and exact 10/20/30% movement component scaling; additive Catch Breath/Webbed Feet swimming; `빠른 발` at exact 3/6/9/12/15% movement component multipliers and its delayed additive Catch Breath acquisition; mutually exclusive `야행성` nighttime and `햇빛 체질` daytime movement at all three levels plus their shared Quick Feet interaction; diagnostic vanilla fishing-rod, breathable-air, freeze-buildup, attack-speed, furnace-fuel, and Long Reach API-surface probes; an entity death/loot API surface probe; Loot Scoop exact 5/10/15% boundaries and a guaranteed level-3 player-kill bonus bundle; and Extra Piece ore-drop tests covering deterministic chance boundaries and block/tool loot under Silk Touch and Fortune. A separate SimulatedPlayer break confirms live `playerBreakBlock` event delivery. The loot surface probe records stable `entityDie` and `entityItemDrop` timing, killer attribution, and whether `LootTableManager.generateLootFromEntity` can read a dead entity. Loot Scoop exercises the death handler against that real event, but the second bundle is independently generated from the loot table and is not asserted to match the original drops. The ground `moveRelative` velocity probe did not produce valid control/level-1 measurements, so it is excluded; client walking and an actual sprint-reset transition remain unverified. The movement tests verify server component values, not visible client motion. The water test measures the production handler's swim-speed ratios. The crop test uses the same handler source copied from BP but supplies a synthetic block-break event payload instead of triggering a real player break. Precise Aim and Last Strength use synthetic projectile-attributed `applyDamage` events with a spawned arrow entity; they do not test actual arrow flight or collision. A physical-arrow experiment failed to hit and is recorded as such in the API compatibility report. The live Extra Piece event test does not assert its random proc during ordinary survival mining. Live crop harvesting, the client-visible drop, mobile/controller navigation and multiplayer still need review.

The simulated-player test cannot provide trustworthy visual UI or a real form selection. Reconnect persistence, client import, mobile/controller navigation, multiplayer, and world restart are not verified by this suite. The runner resets only its own generated world on each run.
