# Bedrock Game Quality Standard

목표는 '작동하는 애드온'이 아니라 **플레이 흐름·정보 전달·시각 표현·애니메이션·소리·성능·안정성이 서로 맞물리는 고품질 게임 경험**이다.

## 외부 게임 레퍼런스 조사 필수

기능·전투·경제·세계·도감·NPC·설명문·UI·아이콘·모델·애니메이션을 새로 기획하거나 크게 변경할 때는 **구현 이전에 실제 외부 게임을 조사한다**. 분야가 다르면 비교할 게임도 바꾼다.

1. 같은 문제를 풀고 있는 외부 게임 2종 이상을 가능하면 고른다.
2. 공식 소개, 실제 플레이 화면·영상 및 유용한 사용자 경험 자료를 확인하고, 서로 다른 해법을 비교한다.
3. 무엇을 참고할지, 왜 이 게임에 맞는지, 무엇을 따라하지 않을지 짧게 명시한다.
4. 화면 정보의 순서·피드백 타이밍·조작 횟수·시각 언어·설명 방식까지 확인한다. 제목이나 이미지 몇 개만 수집하는 것은 조사 완료가 아니다.
5. 설계가 바뀌면 해당 영역의 레퍼런스를 갱신한다. 불필요하게 모든 과거 조사를 반복하지는 않는다.
6. 저작물은 베끼지 않고 디자인 패턴과 사용성의 근거만 재해석한다.

## 플레이어 화면 및 문구

- **개발 로그, TMI, 제작자 설명, 개발자 변명, 테스트 상태, 내부 수치·파일명·명령어·버전 같은 개발자 관점 문구 금지.**
- 안내가 필요한 순간에 '다음 행동'을 짧고 직관적으로 보인다.
- 도감은 '출현 장소 / 획득 재료 / 공략 팁 / 활용 요리'처럼 플레이에 도움이 되는 항목만 우선한다.
- 설명을 여러 창으로 반복하지 않는다. 과잉 튜토리얼, 방대한 수집 과제, 의무 숙련도는 지양한다.
- 한국어/영어, 장문 이름, 빈 목록, 미발견 데이터, 컨트롤러/터치·작은 화면·GUI Scale 변화에서 의미와 조작이 유지되어야 한다.
- UI 정보 계층은 실제 게임을 참고해 설계한다. AI가 임의로 만든 사각형 패널만으로 디자인 완료를 선언하지 않는다.

## 플레이 리듬과 복잡도

- 새로운 기능은 '어떤 결정/재미를 더하는가, 플레이어가 알아야 할 규칙은 몇 개인가, 반복 행동이 늘어나는가'로 평가한다.
- 한 시스템에 두 개 이상의 사실상 동일한 화폐·숙련도·중첩 보너스·보조 연구 트리를 무분별하게 추가하지 않는다.
- 복잡한 사냥법은 특수 몬스터의 선택적 이득으로 두되 일반 사냥의 정상 보상을 빼앗지 않는다.
- 직원/자동화는 일상 반복을 줄이는 장치이지 플레이어가 즐길 모든 행동을 지우는 버튼이 아니다.
- 공장/생산 라인식 불필요한 가공 단계와 강제 대기 타이머를 피한다.

## 그래픽·모델·움직임

레퍼런스 → Blockbench blockout → 실루엣/크기 확인 → 텍스처 → 리그/애니메이션 → 실제 Bedrock 화면 검수 → 효과음/VFX 동기화.

- Minecraft 세계에 자연스러운 비율과 텍스처 밀도를 우선한다.
- 몬스터의 공격은 예고·실제 판정·피격 반응이 일치해야 한다.
- 요리와 가구는 실제 월드에서 정면/측면/야간 조명 하에 확인한다.
- 외부 자산은 허용 라이선스, 모델·텍스처 원본, 수정 내역을 추적한다.
- 디자인 도구 사용 여부만으로 품질을 주장하지 않는다.

## 성능과 실제 검증

- 활성 식당·손님·직원·몬스터 수가 늘어난 최악 조건에서 측정한다.
- 필요하지 않은 월드 전역 반복 검사와 장거리 NPC 실시간 경로 탐색을 피한다.
- 단독 월드, 서버/다중 접속, 비활성 청크, 재접속 후 소유권·재고·거래 상태를 확인한다.
- UI 화면, 터치·컨트롤러, 작은 창에서 실제 캡처를 보고 검수한다.
- JSON PASS 또는 스크립트 정적 검사 PASS는 기능/아트/런타임 PASS가 아니다.

## 완료 판정

각 작업은 기능 검증, 화면 가독성, 모델·애니메이션·효과, 음향, 실패 경로, 성능, 기존 기능 회귀를 합리적인 범위에서 확인한다. 확인하지 못한 것은 `NOT_RUN` 또는 `BLOCKED`로 기록한다.
